[Pvtについて]
フロントのロジックは最低限に留め、生データをサーバサイドに返すことに務める

<研究で使われている主な指標>
平均反応時間/中央反応時間：全体的にどれだけ反応が遅いか
lapse：反応が極端に遅れた回数(基準は500ms以上)
false start：早すぎる反応や画面変化が起こる前の反応
response speed：反応時間の逆数
最速10%/最遅10%：

フロントで記録必須のデータとしては
・実施開始時間
・実施終了時間
・画面の色が変わった時間の配列(ms単位)
・ボタンが押された時間の配列(ms単位)
→false startも記録すべきか？ロジックで解析可能ではあるが。。。

→ペアで送る方式にするのが良さそう
{ "ChangedAt":1000, "ClickedAt":1250 }//正常
{ "ChangedAt":3000, "ClickedAt":2900 }//フライング
{ "ChangedAt":6000, "ClickedAt":9000 }//極端な遅延

どっちか分からない場合はどうする？→例：3000(変化)>6000(ボタン)>9000(変化)

→各変化に対して有効な周辺時間を設ける(-1000、+3000まで)
→一度でも有効時間内にボタンが押されたらそのペアはfix
